### RAG-1 · Gap doc #7 (deepened): Context engineering  — **P1** · THIN · Section D · new turn after Turn 40 (cross-link Turns 31, 55, 58)

*Overlaps gap doc:* #7: same topic. This version adds the vendor APIs and their settings, the clearing-versus-cache trade-off, a "constraint survives compaction" test, and a sourcing fix (#7 cites arXiv 2606.29175, which is an unrelated humanitarian-law paper, [arXiv, 28 Jun 2026](https://arxiv.org/abs/2606.29175)). It keeps #7's verified evidence: Microsoft Agent Framework's harness, GA after Build 2026, bundles context compaction and file memory [InfoQ, 3 Aug 2026](https://www.infoq.com/news/2026/08/agent-framework-harness-ga/). The memory-tool half overlaps #12 (agent memory): cross-link it, don't teach it twice.

**What it is.** Context engineering is deciding, turn by turn, what stays in the model's context window. It covers summarising old history (compaction), clearing stale tool results and thinking by rule (context editing), moving durable state to memory files, and pinning constraints that must never be summarised away, all while protecting the prompt-cache prefix.

**Why now.** Anthropic launched context editing and a memory tool on 29 Sep 2025, reporting +29% (editing) and +39% (editing plus memory) on an agentic-search eval, and 84% fewer tokens on a 100-turn web-search eval [Anthropic, 29 Sep 2025](https://claude.com/blog/context-management). Compaction is now a standard API feature: Anthropic has threshold compaction (beta compact-2026-01-12) and on-demand compaction (beta compact-2026-09-04) and says to "Use on-demand compaction wherever it is available" [Anthropic docs, accessed 26 Sep 2026](https://platform.claude.com/docs/en/build-with-claude/compaction), while OpenAI offers /responses/compact and context_management.compact_threshold [OpenAI docs, accessed 26 Sep 2026](https://developers.openai.com/api/docs/guides/compaction). Chroma tested 18 models and found that "performance grows increasingly unreliable as input length grows" [Chroma Research, 14 Jul 2025](https://www.trychroma.com/research/context-rot). On 23 Feb 2026 Meta's Summer Yue reported that her OpenClaw agent deleted her inbox despite being told to confirm before acting [Summer Yue on X, 23 Feb 2026](https://x.com/summeryue0/status/2025774069124399363); in her own reply she wrote that her real inbox "triggered compaction" and "During the compaction, it lost my original instruction" [Summer Yue on X, 23 Feb 2026](https://x.com/summeryue0/status/2025836517831405980).

**What Vol 2 has today.** Turn 58 Q284 mentions compaction once ("so work survives compaction and restarts"), and Turns 31 (Q149, a timestamp that breaks caching), 32 (Q154–155, context rot) and 55 (subagent isolation) touch nearby ideas, but context editing, tool-result clearing, compaction APIs and pinned constraints are not taught.

**What to teach.**
- Pick the right tool. Context editing is the lightest: it drops bulky tool results or old thinking that can be fetched again, by rule. Compaction summarises the whole history near a threshold. Memory files hold what must outlive any window: the plan, decisions and constraints.
- Set the Anthropic knobs. clear_tool_uses_20250919 defaults to a 100k-token trigger and keeps the last 3 tool uses, with clear_at_least, exclude_tools and clear_tool_inputs [Anthropic docs, accessed 26 Sep 2026](https://platform.claude.com/docs/en/build-with-claude/context-editing). Threshold compaction triggers at 150,000 tokens by default (minimum 50,000), and custom instructions "completely replace" the default summary prompt [Anthropic docs, accessed 26 Sep 2026](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold).
- Treat OpenAI's compaction item as a black box. It is "opaque and not intended to be human-interpretable", so send it back as returned and do not prune it [OpenAI docs, accessed 26 Sep 2026](https://developers.openai.com/api/docs/guides/compaction).
- Manage the cache trade-off. Tool-result clearing "Invalidates cached prefixes when content is cleared" [Anthropic docs, accessed 26 Sep 2026](https://platform.claude.com/docs/en/build-with-claude/context-editing). Clear in large batches (clear_at_least), keep the system prompt and tools at the front behind their own cache breakpoint, and exclude tools whose results you will need again. Manus calls the key-value (KV) cache hit rate "the single most important metric" for production agents [Manus, 18 Jul 2025](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus).
- Pin constraints. Keep hard rules in the system prompt or a pinned memory file that is re-injected after each compaction. Enforce risky actions in code with approval gates, not in text. Tell the summariser what it must preserve.
- Test past the threshold. Run an eval that crosses the compaction trigger and checks that each constraint still holds. On Claude Fable 5.1, Mythos 5.1 and Opus 5.5, thinking blocks before a compaction block are not carried forward, so check quality after compaction too [Anthropic docs, accessed 26 Sep 2026](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold).

**Idea to remember.** Treat the context window as a managed cache: decide what is pinned, summarised, cleared or kept in files, and test that constraints survive compaction.

**Interview questions.**
1. Compaction, context editing and a memory tool: when do you use each? — Context editing drops bulky tool results or old thinking by rule and keeps the dialogue; compaction summarises the whole history near a threshold. Memory files hold the plan, decisions and constraints that must outlive any window, and long-running agents usually need all three.
2. Why can context editing increase your bill? — Clearing tool results changes the prompt prefix, so the cache is invalidated and written again. Clear in large batches, keep the system prompt and tools behind their own cache breakpoint, and exclude tools whose results you will reuse.
3. How do you stop compaction from removing a safety rule? — Keep hard constraints in the system prompt or a pinned memory file re-injected after each compaction, and enforce risky actions in code, not text. Tell the summariser what to preserve, and add an eval that runs past the compaction threshold; the OpenClaw inbox deletion is the reference case.

### RAG-3 · Permission-aware retrieval: ACL ingestion, permission-sync lag and in-place retrieval  — **P1** · THIN · Section E · new turn after Turn 50 (cross-link Turns 47, 52, 71; co-teach source sync with RAG-4)

*Overlaps gap doc:* none. (This is the right home for the Copilot CW1226324 label-enforcement bug, which gap-doc #3 cites under agentic-browser security.)

**What it is.** Making retrieval return only what the asking user may see. That means storing source access-control lists (ACLs) on every chunk (SharePoint, OneDrive, Google Drive, Confluence, Slack), expanding group membership at query time and keeping permissions in sync, or calling the source system's own permission-trimmed retrieval API instead of copying data into a separate index.

**Why now.** In Azure AI Search, SharePoint ACL ingestion is still "(preview)", and incremental ACL updates need the 2026-05-01-preview REST API or later. Parent-scope changes are "not picked up automatically", "Anyone" and "People in your organization" links and guest users are unsupported, and a Microsoft Entra group nested in a SharePoint group is not expanded; Microsoft warns that "If you change SharePoint permissions without triggering an update mechanism, the index serves stale ACL data" [Microsoft Learn, updated 17 Sep 2026](https://learn.microsoft.com/en-us/azure/search/search-indexer-sharepoint-access-control-lists). For the full permission model, the same page recommends a remote SharePoint knowledge source built on the Microsoft 365 Copilot Retrieval API, which retrieves in place with up to 25 results per call and 200 requests per user per hour [Microsoft Learn, 20 Aug 2026](https://learn.microsoft.com/en-us/microsoft-365-copilot/extensibility/api/ai-services/retrieval/overview). Real leaks keep happening: a label-enforcement bug let Copilot Chat summarise confidential-labelled emails in Sent Items and Drafts (advisory CW1226324, detected 21 Jan 2026) [BleepingComputer, 18 Feb 2026](https://www.bleepingcomputer.com/news/microsoft/microsoft-says-bug-causes-copilot-to-summarize-confidential-emails/), and EchoLeak (vulnerability ID CVE-2025-32711) exfiltrated retrieved internal data through what its authors call an "LLM scope violation" [arXiv, 6 Sep 2025](https://arxiv.org/abs/2509.10540).

**What Vol 2 has today.** Turn 50 Q244 ("Why is post-filtering dangerous for permission filters?") and Turn 47 Q231 ("One cache per permission group, or fall back to RAG with filters") treat permissions as a filtered-search problem, Turn 52 Q253 lists "access groups" in chunk lineage and Turn 71 covers on-behalf-of tokens; "acl", "sharepoint", "connector" and "security trimming" get 0 hits.

**What to teach.**
- Ingest ACLs with every chunk and expand groups at query time. List the principals your connector cannot represent (sharing links, guests, nested groups) and decide how to handle each.
- Treat permission-sync lag as a number. State an ACL sync-lag target, drive sync from change notifications, and trigger an explicit resync for parent-scope changes (site, library, folder). Permission changes reach the index only "after that metadata is synchronized" [Microsoft Learn, updated 17 Sep 2026](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview).
- Add a late-binding check: re-verify the user's access to every cited document at answer time.
- Choose copy-and-index or in-place (federated) retrieval. Your own index gives control over chunking, hybrid ranking and cross-source merging, but you own ACL sync, deletion and residency. In-place retrieval keeps permissions and freshness native, but results come back unordered with a cosine-similarity relevanceScore, quotas apply, and merging across sources is your job [Microsoft Learn, 20 Aug 2026](https://learn.microsoft.com/en-us/microsoft-365-copilot/extensibility/api/ai-services/retrieval/overview).
- Run a leak test before go-live. Seed canary documents with known ACLs, query as users inside and outside the groups (including nested groups, sharing links and guests), assert zero leakage, and measure the time from an ACL change to enforcement. Rerun after every connector change.
- Fix oversharing first, and treat labels as a separate layer. Copilot grounds on "data users already have permission to access", and Microsoft's deployment blueprint starts with "Remediate oversharing" [Microsoft Learn, 6 May 2026](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-blueprint-oversharing). Label and data-loss-prevention (DLP) enforcement can fail on its own, as CW1226324 showed.

**Idea to remember.** Retrieval is only as secure as its last permission sync: know your sync lag, test with real users' tokens, and prefer in-place, permission-trimmed retrieval when the source offers it.

**Interview questions.**
1. A user lost access to a SharePoint folder an hour ago. Can your RAG still show them its content? — Yes, if ACLs were copied at ingestion and refresh only on indexer runs, and parent-scope changes may need an explicit resync. Mitigate with change-driven sync, a late-binding permission check on cited documents, or in-place retrieval through the source's permission-trimmed API.
2. Copy-and-index or federated retrieval? — Your own index gives control over chunking, hybrid ranking and merging, but you own ACL sync, deletion and residency. Federated retrieval (the Copilot Retrieval API, or a Model Context Protocol (MCP) server called with the user's delegated token) keeps permissions and freshness native, but results are unordered, quotas apply (25 results per call, 200 requests per user per hour) and cross-source merging is yours.
3. How do you test permission trimming before go-live? — Seed canary documents with known ACLs and run the same queries as users inside and outside the groups, covering nested groups, sharing links and guests. Assert zero leakage, measure the time from an ACL change to enforcement, and rerun after every connector change.

### RAG-5 · Gap doc #14 (deepened): Text-to-SQL and semantic layers  — **P1** · MISSING · Section E · new turn after Turn 51

*Overlaps gap doc:* #14: same topic, and it agrees the topic is MISSING. This version adds the dated evidence #14 lacks (its "most common enterprise FDE request" line has no source), current benchmark numbers and their contamination risk, the Open Semantic Interchange / Apache Ossie spec, MetricFlow under Apache 2.0, first-party natural-language-to-SQL agents and spreadsheet agents. It raises the priority from P2 to P1.

**What it is.** Answering questions over databases and spreadsheets by generating queries or code instead of embedding rows. The model links the question to the schema, grounds it in a governed semantic or metrics layer (dbt MetricFlow, Snowflake semantic views, Databricks metric views, LookML, Cube), runs read-only with limits, asks when the question is ambiguous, and is judged on execution results.

**Why now.** On the enterprise-style Spider 2.0 benchmark, o1-preview scored 21.3%, against 91.2% on Spider 1.0 [arXiv, 12 Nov 2024](https://arxiv.org/abs/2411.07763). Leaders are still short of humans: the best BIRD test execution accuracy is 82.39% (Huawei's DataGallery-Text2SQL, dated 7 Sep 2026) against 92.96% for humans [BIRD leaderboard, accessed 26 Sep 2026](https://bird-bench.github.io/), and the self-reported Spider 2.0-Lite leader is at 76.23% [Spider 2.0 leaderboard, accessed 26 Sep 2026](https://spider2-sql.github.io/). Vendors are converging on semantic layers: the Open Semantic Interchange (OSI), announced on 23 Sep 2025 by Snowflake and 16 partners [Snowflake, 23 Sep 2025](https://www.snowflake.com/en/news/press-releases/snowflake-salesforce-dbt-labs-and-more-revolutionize-data-readiness-for-ai-with-open-semantic-interchange-initiative/), published its first spec on 27 Jan 2026 [Snowflake, 27 Jan 2026](https://www.snowflake.com/en/blog/open-semantic-interchanges-specs-finalized/) and entered the Apache Incubator as Apache Ossie in July 2026 [Apache Ossie, 10 Jul 2026](https://ossie.apache.org/updates/ossie-enters-apache-incubator/), and dbt moved MetricFlow to Apache 2.0 on 14 Oct 2025 [dbt Labs, 14 Oct 2025](https://www.getdbt.com/blog/open-source-metricflow-governed-metrics). First-party agents are shipping: BigQuery conversational analytics went GA on 23 Jun 2026 [Google Cloud release notes, 23 Jun 2026](https://docs.cloud.google.com/bigquery/docs/release-notes), and Microsoft reported 57.2% on SpreadsheetBench for Agent Mode in Excel [Microsoft 365 blog, 29 Sep 2025](https://www.microsoft.com/en-us/microsoft-365/blog/2025/09/29/vibe-working-introducing-agent-mode-and-office-agent-in-microsoft-365-copilot/).

**What Vol 2 has today.** Nothing found after searching for: text-to-sql, nl2sql, semantic layer, dbt, metricflow, lookml, snowflake, bigquery, spreadsheet, excel, warehouse; the nearest is Turn 51 Q251 on safe text-to-Cypher ("Read-only credentials, query validation or allow-lists, timeouts, result limits and error-feedback retries").

**What to teach.**
- Explain why raw text-to-SQL fails in enterprises: schemas with thousands of columns, ambiguous names, undocumented join paths, and business definitions ("active customer", fiscal calendars) that the schema does not hold.
- Ground queries in a semantic layer, so the model picks governed metrics and dimensions instead of writing joins. dbt's rule: "Metrics should not be probabilistic or depend on an LLM guessing each calculation" [dbt Labs, 14 Oct 2025](https://www.getdbt.com/blog/open-source-metricflow-governed-metrics). Snowflake claims Cortex Analyst with a semantic model is "close to 2x more accurate" than single-shot SQL from GPT-4o (vendor claim) [Snowflake Engineering, 14 Aug 2024](https://www.snowflake.com/en/engineering-blog/snowflake-cortex-analyst-behind-the-scenes/).
- Execute safely: a read-only role with row- and column-level security, a SELECT-only allow-list, cost, timeout and row limits, a dry-run or EXPLAIN step, warehouse masking policies for personal data, a log of every query, and the SQL or metric definition shown next to the answer.
- Handle ambiguity by asking a clarifying question when a question has more than one reading. Interactive tasks stay hard: BIRD-Interact top success rates are about 16–24% [BIRD leaderboard, accessed 26 Sep 2026](https://bird-bench.github.io/).
- Evaluate by execution. Use real business questions with gold results, compare result sets rather than SQL strings, and track accuracy per metric and per table. Treat public leaderboards as self-reported and contamination-prone: Spider 2.0 gold answers have been public "for self-evaluation" since 24 Dec 2024, and the Spider 2.0-Snow top score is 96.70% [Spider 2.0 leaderboard, accessed 26 Sep 2026](https://spider2-sql.github.io/).
- Cover spreadsheet agents. SpreadsheetBench v1 (912 real forum tasks) tops out at 70.48%, but v2 (321 business-workflow tasks) only at 34.89% [SpreadsheetBench, accessed 26 Sep 2026](https://spreadsheetbench.github.io/).

**Idea to remember.** Don't let the model invent business logic: have it pick governed metrics and dimensions from a semantic layer, run read-only with limits, and check answers by executing them, not by reading the SQL.

**Interview questions.**
1. Why is raw text-to-SQL unreliable in enterprises, even with strong models? — Real schemas have thousands of columns, ambiguous names, undocumented joins and business definitions the schema does not contain; on Spider 2.0's enterprise tasks o1-preview fell to about 21%. A semantic layer supplies the definitions, so the model picks metrics and dimensions instead of writing joins.
2. How do you make an analytics agent safe to run against production data? — Give it a read-only role with row- and column-level security, a SELECT-only allow-list, cost, timeout and row limits, a dry-run step and warehouse masking policies. Log every query, and show the SQL or metric definition next to the answer.
3. How do you evaluate a text-to-SQL assistant? — Compare execution results against gold results on real business questions, not SQL strings, and include ambiguous questions where the right move is to ask. Treat public leaderboards with caution: they are self-reported, near saturation (Spider 2.0-Snow is above 96%), and their gold answers are public.

### RAG-4 · Index freshness: incremental (CDC) ingestion, delete propagation, freshness targets and conflicting versions  — **P2** · THIN · Section E · extend Turn 52 (co-teach the change-feed machinery with RAG-3)

*Overlaps gap doc:* none

**What it is.** Keeping a retrieval index consistent with changing sources. It covers consuming change feeds (change data capture, CDC), re-embedding only changed chunks, propagating deletes and moves, recovering from forced resyncs, setting a target lag per source, and ranking correctly when several versions of a document exist.

**Why now.** Freshness is now an explicit platform setting. Snowflake Cortex Search refreshes on TARGET_LAG, needs change tracking, and with primary keys processes only the rows that changed [Snowflake docs, accessed 26 Sep 2026](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-search/cortex-search-overview); Databricks Delta Sync indexes need a change data feed and reuse embeddings for unchanged rows, but storage-optimized endpoints do not support continuous sync [Databricks docs, accessed 26 Sep 2026](https://docs.databricks.com/aws/en/generative-ai/vector-search). The source APIs are eventually consistent: Microsoft Graph delta queries say "Expect varying delays", can return 410 Gone and force a full resync, and directory-object delta tokens are valid for seven days [Microsoft Learn, updated 14 May 2026](https://learn.microsoft.com/en-us/graph/delta-query-overview). In OneDrive and SharePoint delta, renaming a folder does not return its descendants, so you must "always track items by id" [Microsoft Learn, updated 6 Jun 2026](https://learn.microsoft.com/en-us/graph/api/driveitem-delta).

**What Vol 2 has today.** Turn 47 names freshness only as a selection criterion (Q230, "Large or fast-changing corpora"), Turn 52 Q253 gives each chunk a "document version" and "content hash" but never uses them for incremental sync, and Turn 87 Q432 covers re-embedding on model change; "incremental", "cdc", "change data" and "re-index" get 0 hits.

**What to teach.**
- Read change feeds instead of re-embedding nightly: Graph delta, Drive changes, Delta change data feed, warehouse table change tracking.
- Chunk deterministically and hash each chunk. Re-embed only changed hashes, upsert by stable IDs (track items by ID, not path), and write tombstones for deletes.
- Design for resync. When a token expires or the API returns 410 Gone, run a full enumeration and reconcile it with local state. Use idempotent upserts, a scheduled reconciliation job, and alerts on resync frequency and freshness lag.
- Set a freshness target (a service-level objective, SLO) per source and monitor actual lag against it.
- Rank with versions. Store version, effective date and authority, dedupe near-duplicates, boost or filter to the latest effective version, show the date in the citation, and say so when versions disagree.
- Reuse the same feeds for permissions (RAG-3). Graph's "Prefer: deltashowsharingchanges" header flags permission changes but needs Sites.FullControl.All [Microsoft Learn, updated 6 Jun 2026](https://learn.microsoft.com/en-us/graph/api/driveitem-delta).

**Idea to remember.** Freshness is a pipeline property with an SLO: consume change feeds, hash chunks so only changes are re-embedded, propagate deletes, and prefer the newest authoritative version at ranking time.

**Interview questions.**
1. How do you avoid re-embedding the whole corpus every night? — Read the sources' change feeds (Graph delta, Drive changes, Delta change data feed, table change tracking). Chunk deterministically, hash each chunk, re-embed only changed hashes, upsert by stable IDs and write tombstones for deletes.
2. Your delta token expired, or the API returned 410 Gone. What now? — Run a full enumeration and reconcile it with local state, applying the server's deletes. Plan for it in advance with idempotent upserts, a scheduled reconciliation job, and alerts on resync frequency and freshness lag.
3. Two versions of the same policy both match a query. What do you do? — Store version, effective date and authority as metadata, and dedupe near-duplicates. At ranking time boost or filter to the latest effective version, show the date in the citation, and have the answer say so when versions disagree.

### RAG-6 · LLM functions inside the data platform: Snowflake Cortex AISQL, Databricks AI Functions, BigQuery AI  — **P2** · MISSING · Section E · new turn after Turn 52 (cross-link Turns 35, 91; RAG-5, RAG-7)

*Overlaps gap doc:* none

**What it is.** LLM operators you call from SQL: classify, filter, extract, score, summarise-aggregate, parse document, embed and semantic join. They run batch inference where the data and its governance already live, and the query optimiser treats model calls as a cost to minimise.

**Why now.** All three major platforms ship GA sets. Snowflake lists AI_COMPLETE, AI_CLASSIFY, AI_FILTER, AI_AGG, AI_EXTRACT and others as GA, with AI_PARSE_DOCUMENT still in preview [Snowflake docs, accessed 26 Sep 2026](https://docs.snowflake.com/en/user-guide/snowflake-cortex/aisql), and Databricks lists ai_parse_document, ai_extract and ai_classify as GA [Databricks docs, updated 25 Sep 2026](https://docs.databricks.com/aws/en/large-language-models/ai-functions). BigQuery's AI.IF, AI.SCORE and AI.CLASSIFY went GA on 13 Apr 2026, with an optimized mode for AI.IF and AI.CLASSIFY in preview [Google Cloud release notes, 13 Apr 2026](https://docs.cloud.google.com/bigquery/docs/release-notes). Snowflake's Cortex AISQL paper reports 2–8x speedups from AI-aware query optimisation, 2–6x from model cascades "while maintaining 90-95% of oracle model quality", and 15–70x from rewriting semantic joins [arXiv, 10 Nov 2025, v3 revised 7 Apr 2026](https://arxiv.org/abs/2511.07663); follow-on work gives 11.4x only as an upper bound under independence and "a realistic figure near 8x" [arXiv, 27 Aug 2026](https://arxiv.org/abs/2608.27244).

**What Vol 2 has today.** Nothing found after searching for: snowflake, databricks, bigquery, cortex, warehouse, lakehouse; the nearest is Turn 35 on provider batch APIs (Q168–Q171) and Turn 91 on cloud cost management (FinOps).

**What to teach.**
- Know the operator set: classify, filter, extract, score, aggregate-summarise, parse and embed, run as batch inference inside the governed platform.
- Decide between platform functions and your own pipeline. Use the platform when governance (row access, masking, lineage, residency) must stay there, the task is row-wise, and SQL users will own it. Build your own when you need custom models or prompts, multi-step agentic logic, or portability across platforms.
- Contain cost. WHERE AI_FILTER(...) can call the model on every row, including rows produced by joins. Apply cheap relational filters first, use cascades or distilled optimized modes [Google Cloud docs, accessed 26 Sep 2026](https://docs.cloud.google.com/bigquery/docs/generative-ai-overview), prototype on a sample, count tokens up front and set budgets.
- Validate generated columns before they feed dashboards. Label a stratified sample, measure per-class precision and recall, pin the model version, and re-check on every model upgrade (Turn 87).
- Keep it distinct from RAG-5: this is batch enrichment as a SQL operator, while RAG-5 is analytics question answering. The same extract functions also serve extraction pipelines (RAG-7).

**Idea to remember.** When the data lives in a warehouse, bring the model to the data as a SQL operator, and let relational filters, cascades and the optimiser cut the number of model calls you pay for.

**Interview questions.**
1. When would you use warehouse AI functions instead of your own batch pipeline? — When governance (row access, masking, lineage, residency) must stay in the platform, the task is row-wise, and SQL users will own it. Build your own pipeline for custom models or prompts, multi-step agentic logic, or portability.
2. Why can WHERE AI_FILTER(...) blow up cost, and how do you contain it? — It can call the model on every row, including rows produced by joins. Apply cheap relational filters first, use cascades or optimized modes, prototype on a sample and set budgets; Snowflake reports 2–8x speedups from AI-aware query optimisation and 15–70x from rewriting semantic joins.
3. How do you validate an LLM-generated classification column before it feeds dashboards? — Label a stratified sample and measure per-class precision and recall. Compare prompt and model variants, pin the model version, and re-run the check on every model upgrade.

### RAG-7 · Structured extraction at scale (IDP): confidence-routed review, source grounding and field-level evaluation  — **P2** · THIN · Section E · extend Turn 42 (cross-link Turns 36, 64, 105; threshold calibration taught once in models MOD-3)

*Overlaps gap doc:* none

**What it is.** Intelligent document processing (IDP) is a production pipeline that turns documents into data: it classifies and splits document packets, extracts schema fields, checks them against business rules, attaches a confidence score and source location to each field, and sends low-confidence fields to human review. Success is measured by field-level accuracy and the straight-through-processing (STP) rate, the share processed with no human review.

**Why now.** Managed services now ship these parts. Amazon Bedrock Data Automation went GA on 3 Mar 2025 [AWS What's New, 3 Mar 2025](https://aws.amazon.com/about-aws/whats-new/2025/03/amazon-bedrock-data-automation-generally-available/), and its user guide lists "built-in safeguards, such as visual grounding and confidence scores" alongside classification, normalisation and validation [AWS docs, accessed 26 Sep 2026](https://docs.aws.amazon.com/bedrock/latest/userguide/bda.html). Azure Content Understanding's GA API (2025-11-01) returns a 0–1 confidence and source grounding for each field, "enabling straight-through processing", and the 2026-06-01 preview adds an agentic mode [Microsoft Learn, updated 24 Sep 2026](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/overview). Warehouse functions such as Databricks ai_parse_document and ai_extract (both GA) turn the same job into a SQL call [Databricks docs, updated 25 Sep 2026](https://docs.databricks.com/aws/en/large-language-models/ai-functions).

**What Vol 2 has today.** Turn 42 covers parsing (Q207, parser evaluation) and Turn 105 Q521 answers "Specific prompts, schemas, crops..., validation checks in code, grounding boxes and human review for failures", with Turn 36 (structured outputs) and Turn 64 (risk-tiered review) nearby; "straight-through" and "invoice" get 0 hits.

**What to teach.**
- Classify and split document packets before extracting fields.
- Require per-field confidence and source grounding (bounding boxes or spans). Reviewers can check a field in seconds by jumping to its source, and a field with no locatable source is a strong hallucination signal.
- Put business-rule checks in code: checksums on bank-account (IBAN) and VAT numbers, totals equal to the sum of line items, date ranges, allowed values, and cross-document checks such as invoice against purchase order. A failed check sends the field to review whatever the confidence says.
- Route by per-field thresholds set from a labelled field-level set and matched to each field's error budget (an IBAN needs a stricter one than a notes field). Teach the calibration method once, in MOD-3.
- Report the STP rate and the error rate after auto-acceptance as the business key performance indicators (KPIs).
- Choose between a managed IDP service, warehouse SQL functions (RAG-6) and a custom pipeline.

**Idea to remember.** An extraction system's product is not JSON but a decision per field, auto-accept or human review, so calibrate confidence against field-level accuracy and report the straight-through rate.

**Interview questions.**
1. How do you set the auto-accept threshold for extracted fields? — Build a labelled field-level set and plot accuracy against confidence for each field, then pick thresholds that meet each field's error budget. Check calibration on fresh documents, and monitor both STP rate and the error rate after acceptance.
2. Which checks belong in code rather than in the model? — Checksums (IBAN, VAT), totals equal to the sum of line items, date ranges, allowed values, and cross-document consistency such as invoice against purchase order. A failure routes the field to review whatever the confidence says.
3. Why pay for source grounding (bounding boxes or spans)? — Reviewers can verify a field in seconds by jumping to its source, and auditors can trace every value. A field with no locatable source is a strong hallucination signal.

### RAG-8 · Agentic retrieval: retrieval as tools, planning cost, and index vs grep for code  — **P2** · THIN · Section E · extend Turns 47 and 56 (cross-link Turn 61)

*Overlaps gap doc:* #7 lists just-in-time retrieval as a context tactic, and #19 covers web search as one source type. This adds retrieval-as-tool for everyday RAG, the cost and latency of query planning, and the evidence on index vs grep for code.

**What it is.** Retrieval driven by the model rather than a fixed pipeline. The model splits the question into sub-queries, picks sources, runs searches in parallel or in turn, judges whether it has enough and stops; because retrieval is exposed as tools (search, grep/glob, SQL, MCP), you must choose between a pre-built index and just-in-time search.

**Why now.** Azure AI Search made agentic retrieval the base of Foundry IQ knowledge bases, but its GA 2026-04-01 REST API covers only "minimal, extractive retrieval"; LLM query planning is in 2026-08-01-preview, is billed per token, and "adds latency compared to a single-query pipeline" [Microsoft Learn, updated 17 Sep 2026](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-overview). The retriever still matters inside agents: on BrowseComp-Plus, GPT-5 scored 55.9% with BM25 keyword search but 70.1% with the Qwen3-Embedding-8B retriever, and needed fewer searches [arXiv, 8 Aug 2025](https://arxiv.org/abs/2508.06600). For code, Anthropic says Claude Code's grep/glob just-in-time retrieval works by "bypassing the issues of stale indexing" [Anthropic Engineering, 29 Sep 2025](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), while Cursor measured 12.5% higher offline accuracy on average (6.5–23.5% by model) from adding semantic search, plus an online code-retention gain that rises to 2.6% on codebases of 1,000+ files [Cursor, 6 Nov 2025](https://cursor.com/blog/semsearch).

**What Vol 2 has today.** Turn 56 teaches plan-search-read-verify for deep research (Q273), stopping rules (Q275) and final citation checks (Q276), and Turn 47 Q232 names "agentic retrieval" as one hybrid pattern; nothing covers retrieval-as-tool for everyday RAG, planning cost, or index vs grep for code.

**What to teach.**
- Route by question type. Use single-shot RAG for simple single-fact questions under tight latency budgets, and agentic retrieval for multi-part, comparative, conversational or cross-source questions.
- Expose retrieval as tools (search, grep/glob, SQL, MCP) and budget the extra LLM calls and latency that planning adds.
- Stop loops and early give-ups: cap tool calls, require a sufficiency check per sub-question, deduplicate queries, and log the plan and activity (Azure returns an activity log).
- Evaluate recall of the required evidence, not only final-answer accuracy.
- Keep a strong retriever under the agent; on BrowseComp-Plus the better retriever raised accuracy and cut searches.
- For code, expose both grep/glob (exact, always fresh, good for identifiers) and semantic search (finds concepts when you don't know the names); Cursor says the two together give the best outcomes.

**Idea to remember.** Let the model plan retrieval, but keep a good index underneath: agentic search multiplies the value of a strong retriever and exposes the cost of a weak one.

**Interview questions.**
1. When do you choose single-shot RAG over agentic retrieval? — Single-shot for simple single-fact questions under tight latency budgets; agentic for multi-part, comparative, conversational or cross-source questions. Planning adds LLM cost and latency (billed per token in Azure's implementation), so route by question type.
2. Grep or embeddings for code retrieval? — Grep and glob are exact, always fresh and need no index, which suits identifiers; semantic search finds concepts when you don't know the names. Cursor measured 12.5% higher offline accuracy on average, and in online A/B tests a code-retention gain that rises to 2.6% on codebases of 1,000+ files; it says grep plus semantic search together give the best outcomes.
3. How do you stop an agentic retriever from looping or giving up too early? — Budget tool calls, require a sufficiency check for each sub-question, deduplicate queries, and log the plan and activity. Evaluate recall of the required evidence, not only final-answer accuracy.

### RAG-9 · Citation and attribution engineering: span-level citations, citation checking and long-form factuality  — **P2** · THIN · Section E · extend Turns 49 and 14

*Overlaps gap doc:* none

**What it is.** Designing answers so each claim links to an exact source span the user can check. It combines API-native citations, automatic claim-to-source verification, long-form factuality metrics (claim-level precision and recall) and a user experience (UX) that makes checking cheap.

**Why now.** Citation failure is well documented: in a Tow Center test of eight AI search tools on 1,600 queries, the tools misidentified or mis-cited the source in more than 60% of queries (Grok 3 94%, Perplexity 37%), and 154 of Grok 3's 200 citations led to error pages [Columbia Journalism Review, 6 Mar 2025](https://www.cjr.org/tow_center/we-compared-eight-ai-search-engines-theyre-all-bad-at-citing-news.php). Damien Charlotin's database lists 2,079 court and tribunal decisions involving hallucinated content, mostly fabricated citations [AI Hallucination Cases database, updated 25 Sep 2026](https://www.damiencharlotin.com/hallucinations/). Anthropic's Citations API launched on 23 Jan 2025 [Simon Willison, 24 Jan 2025](https://simonwillison.net/2025/Jan/24/anthropics-new-citations-api/), and Anthropic reports that Endex cut source hallucinations from 10% to 0% with it [Anthropic, Citations API launch post](https://claude.com/blog/introducing-citations-api). No model has solved grounding: in the FACTS Benchmark Suite the top score is 68.8% (Gemini 3 Pro) and all evaluated models are below 70% [Google DeepMind, 9 Dec 2025](https://deepmind.google/blog/facts-benchmark-suite-systematically-evaluating-the-factuality-of-large-language-models/).

**What Vol 2 has today.** Turn 14 Q67 ("Split the answer into claims and check each against the cited sources with a judge or entailment model"), Turn 56 Q276, Turn 43 ("citations back to the exact page and figure"), Turn 49 Q238 (faithfulness) and Turn 32 Q156 (quotes before the answer) teach the core, but not API-native citations, citation precision and recall, long-form factuality benchmarks or the checking UX.

**What to teach.**
- Separate three measures: faithfulness (is the whole answer supported by the context), citation precision (does each cited source support its sentence) and citation recall (does every claim that needs a source have one).
- Generate citations from source spans. Pass documents as structured sources and use native citation features, or require quote-then-answer, and resolve each citation to a stable document, page and offset.
- Verify before display: run an entailment or judge check on every claim–citation pair, and drop or flag unsupported claims.
- Evaluate long-form factuality. Split answers into atomic claims, check them against the sources (grounded) or by search (open-world), report the supported share plus a completeness term, and calibrate the judge on human labels. Reference points: FACTS Grounding, with documents up to 32k tokens [Google DeepMind, 17 Dec 2024](https://deepmind.google/discover/blog/facts-grounding-a-new-benchmark-for-evaluating-the-factuality-of-large-language-models/), and SAFE/LongFact, which checks claims by search at over 20x lower cost than human annotators [arXiv, 27 Mar 2024](https://arxiv.org/abs/2403.18802).
- Make checking one click: show the quoted span on hover and link to the page anchor.

**Idea to remember.** A citation is a testable claim: generate it from source spans, verify it automatically, measure citation precision and recall, and make checking one click for the user.

**Interview questions.**
1. Faithfulness vs citation accuracy: what's the difference? — Faithfulness asks whether the answer as a whole is supported by the retrieved context; citation precision asks whether each cited source supports its sentence, and citation recall whether every claim that needs a source has one. An answer can be faithful and still mis-cited.
2. How do you implement verifiable citations? — Pass documents as structured sources and use native citation features that return quoted spans (or require quote-then-answer), and resolve each citation to a stable document, page and offset. Run an entailment or judge check on every claim–citation pair, and drop or flag unsupported claims before display.
3. How do you evaluate long-form factuality? — Split the answer into atomic claims and check each against the sources (grounded) or via search (open-world, SAFE-style), then report the share of supported claims plus a completeness term. Calibrate the judge on human labels; FACTS Grounding and LongFact are reference benchmarks.

### RAG-10 · Cold-start RAG evaluation: synthetic questions, LLM relevance labels and their biases  — **P2** · THIN · Section E · extend Turn 49

*Overlaps gap doc:* none

**What it is.** Building a first evaluation set when the customer has no labelled questions. You generate questions and reference answers from their corpus, label retrieval relevance with LLM judges, and correct the distribution and circularity biases that both methods bring.

**Why now.** Tooling makes generation easy: Ragas builds a knowledge graph of the corpus and synthesises single- and multi-hop queries across personas [Ragas docs, accessed 26 Sep 2026](https://docs.ragas.io/en/stable/concepts/test_data_generation/rag/), and UMBRELA, an open reproduction of Bing's LLM relevance assessor, was adopted for the TREC (Text REtrieval Conference) 2024 RAG track [arXiv, 10 Jun 2024](https://arxiv.org/abs/2406.06519). IBM's "Know Your RAG" warns that public Q&A sets "can lead to non-optimal systems design" and that "common tools for RAG dataset generation can lead to unbalanced data" [arXiv, 29 Nov 2024](https://arxiv.org/abs/2411.19710). Clarke and Dietz argue that "LLM-based relevance assessment still can't replace human relevance assessment", partly because systems that use LLM rerankers get circularly favoured [arXiv, 22 Dec 2024, revised 19 Jan 2026](https://arxiv.org/abs/2412.17156).

**What Vol 2 has today.** Turn 49 assumes a golden set already exists (Q241, "Run retrieval and judged metrics in CI on a golden set"; Q242, unanswerable questions; Q240, judge calibration), and Turns 23 and 63 use synthetic data only for training and simulated users; "relevance label" and "relevance judg" get 0 hits.

**What to teach.**
- Generate a first set per document section with an LLM, covering single-hop, multi-hop, comparison and unanswerable questions across personas.
- Stratify by source and question type, have subject-matter experts review and edit a sample, and swap in real logged questions as soon as the pilot runs.
- Know the biases. Synthetic questions share words with their source chunk (which inflates keyword and embedding recall), skew towards easy single-chunk questions, carry the generator's style, and miss real users' messy phrasing and out-of-scope requests.
- Label relevance with an LLM for scale, but calibrate it against human labels, avoid the same model family as your reranker, and keep a human-judged slice for release decisions.

**Idea to remember.** Synthetic questions give you a baseline in a day, but they test what the generator finds easy: stratify them, mix in real user questions early, and calibrate LLM relevance labels against a human-labelled slice.

**Interview questions.**
1. How do you build an eval set in week one with no labelled data? — Generate questions per document section with an LLM, covering single-hop, multi-hop, comparison and unanswerable types, and stratify by source and question type. Have subject-matter experts review a sample, and swap in real logged questions as soon as the pilot runs.
2. What biases do synthetic questions introduce? — They share words with their source chunk, which inflates keyword and embedding recall, and they skew towards easy single-chunk questions in the generator's style. They miss the messy phrasing and out-of-scope requests of real users; IBM's "Know Your RAG" documents the skewed distributions.
3. Can you use an LLM to label retrieval relevance? — Yes, for scale (UMBRELA was used in the TREC 2024 RAG track). Calibrate it against human labels, avoid the same model family as your reranker (circularity), and keep a human-judged slice for release decisions.

### RAG-11 · Managed RAG and hosted file search: build vs buy  — **P2** · THIN · Section E · extend Turn 50 (cross-link Turn 72 and RAG-3)

*Overlaps gap doc:* none

**What it is.** Provider-hosted retrieval that chunks, embeds, indexes and cites for you behind one API tool or knowledge-base object (Gemini File Search, OpenAI file_search, Azure Foundry IQ, Bedrock Knowledge Bases). The engineering decision is whether it is good enough, and what you give up: chunking and ranking control, per-user permission trimming, eval visibility, residency and portability.

**Why now.** Google launched the Gemini API File Search tool on 6 Nov 2025 as "a fully managed RAG system built directly into the Gemini API", with indexing at $0.15 per 1M tokens, free storage and query-time embeddings, and automatic citations [Google, 6 Nov 2025](https://blog.google/innovation-and-ai/technology/developers-tools/file-search-gemini-api/). OpenAI's hosted file_search tool offers vector stores, automatic chunking and embedding, semantic plus keyword search and metadata filters [OpenAI docs, accessed 26 Sep 2026](https://developers.openai.com/api/docs/guides/tools-file-search), and it is OpenAI's retrieval path now that the Assistants API was removed on 26 Aug 2026 [OpenAI deprecations page, deprecation announced 26 Aug 2025](https://developers.openai.com/api/docs/deprecations). Microsoft positions Azure AI Search as the base of Foundry IQ, "the managed knowledge layer that transforms enterprise content into reusable, permission-aware knowledge bases for agents" [Microsoft Learn, updated 17 Sep 2026](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-overview).

**What Vol 2 has today.** Turn 50 covers self-run vector stores ("often the database they already have") and Turn 72 Q353 lists what managed agent platforms provide with no managed retrieval; "file search", "bedrock", "vertex" and "foundry" get 0 hits, and "knowledge base" appears only in the cache-augmented generation (CAG) sense (Q228).

**What to teach.**
- Know what hosted file search does for you (chunk, embed, index, cite) and what it hides (chunking and ranking control, and the retrieved chunks you need for evaluation).
- Know when it is enough: a modest corpus, uniform access with no per-user ACLs, a customer already on that provider, and default chunking that passes your eval set.
- Check before production. How are per-user permissions enforced (separate stores, metadata filters, or not at all; OpenAI's guide does not describe per-user trimming)? Where do data and embeddings live, and for how long? How do deletes propagate? Are retrieved chunks exposed so you can measure context recall? What are the rate limits, quotas and cost model (indexing tokens, storage, per-call fees)?
- Know the rebuild triggers: permission trimming, custom parsing or chunking, hybrid tuning, cross-provider portability, or retrieval metrics the service does not expose.
- Compare with in-place retrieval (RAG-3). The Copilot Retrieval API needs no separate index but caps calls at 25 results and 200 requests per user per hour [Microsoft Learn, 20 Aug 2026](https://learn.microsoft.com/en-us/microsoft-365-copilot/extensibility/api/ai-services/retrieval/overview).

**Idea to remember.** Hosted file search gets you a working RAG in a day; check up front that it can trim by user permission, expose its retrieval for evaluation and meet residency needs, because those are what force a rebuild.

**Interview questions.**
1. When is a provider's hosted file-search tool enough? — When the corpus is modest, access is uniform (no per-user ACLs), you already use that provider, and default chunking passes your eval set. Move to your own pipeline when you need permission trimming, custom parsing or chunking, hybrid tuning, cross-provider portability, or retrieval metrics the hosted tool does not expose.
2. What must you verify before putting a hosted RAG service in production? — How per-user permissions are enforced, where data and embeddings are stored and for how long, how deletes propagate, and whether retrieved chunks are exposed so you can measure context recall. Also check rate limits, quotas and the cost model (indexing tokens, storage, per-call fees).
